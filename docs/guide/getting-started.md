# Getting started

## Requirements

- Node 22 or later, and `git`.
- Where your code lives, and awaywork pushes branches and opens draft PRs:
  - GitHub: [`gh`](https://cli.github.com) logged in.
  - Bitbucket Cloud: [`twg`](https://developer.atlassian.com/cloud/twg-cli/) logged in and an SSH key, see [Bitbucket and Jira](./config/sources.md#bitbucket-and-jira).
- At least one agent CLI, logged in with your subscription:
  - [Claude Code](https://code.claude.com): logged in, or `CLAUDE_CODE_OAUTH_TOKEN` from `claude setup-token`.
  - [Codex](https://developers.openai.com/codex): `codex login`.
  - [Cursor](https://cursor.com/docs/cli/overview): its `agent` CLI and a `CURSOR_API_KEY`, even on your machine ([why](./config/providers.md#providers)).
  - Any other, opencode, Amp and friends: a command that runs it on a prompt file ([Bring your own CLI](./config/providers.md#bring-your-own-cli)).
- Where your tasks live, one [source](./config/sources.md) or more:
  - GitHub: your issues, your PRs and those awaiting your review. `gh` is enough.
  - Asana, Linear or Jira Cloud: a personal access token, a personal API key or an Atlassian API token ([which](./config/sources.md#tracker-tokens)).
  - Anything else, an internal board, Sentry errors, a list of chores: a command, in any language, that prints your items as JSON ([Custom sources](./config/custom-sources.md)).
  - No tracker at all: [routines](./config/sources.md#routines) make items from the clock.

## Install

```sh
npm install -g awaywork
awaywork --help
```

## Configure

```sh
awaywork init
```

`init` opens Claude Code on `/away set up awaywork`, and the [`/away` skill](./away.md) does the setup with you in a few rounds of questions. No awaywork plugin in Claude Code yet? It offers to install it first:

```text
$ awaywork init
◇  Install the awaywork plugin for Claude Code? It runs claude plugin marketplace add AndreaProvenzale/awaywork, then
│  claude plugin install awaywork@awaywork
│  Yes
✔ Successfully added marketplace: awaywork (declared in user settings)
✔ Successfully installed plugin: awaywork@awaywork (scope: user)
│
●  Opening Claude Code on /away set up awaywork; /exit comes back here
```

Say no and that one session loads the plugin from the npm package instead (`--plugin-dir`), nothing installed. The setup in full, and the pane `/away` opens once there's a config, are in [`/away` in Claude Code](./away.md). Run `init` again with a config there and `/away` tells you where it stands and what you could change.

No Claude Code? `init` says what to do instead:

- Codex gets the same plugin: see [Codex and friends](./agents.md#codex-and-friends).
- Any agent that loads skills can take them from the package.
- `awaywork init --yes` asks nothing and writes the detected defaults, for a container or CI.

Or write a minimal config by hand:

```yaml
providers: [claude]
repos:
  acme/*:
sources:
  github: {}
queue:
  - skill: fix
    where: { type: pr, mine: true, checks: failing }
```

With no [`queue`](./how-it-works.md#the-queue), nothing runs. GitHub issues need a rule of their own, e.g. `implement` for issues labelled `awaywork` (see [Configuration](./config/index.md)). awaywork reads the issues assigned to you, so assign yourself too: the label alone plans nothing, unless a [`search`](./config/sources.md) reads it.

Check it:

```sh
awaywork doctor   # the config, binaries, credentials, quota, sources
```

## Preview the next run

```sh
awaywork plan
```

![awaywork plan loading its steps and showing the next run's units, then awaywork report on the night's run: a review report opened and a draft PR's diff](/demo/quickstart.gif)

`plan` reads your sources and each provider's quota and shows what a run would do, without running an agent. In a terminal it opens at once and shows each step as it loads:

## Run one unit

```sh
awaywork run --dry-run         # clone, context and prompt, no agent
awaywork run --unit api#1      # one real unit
awaywork report                # browse the last run; piped, its morning report
```

`run`'s options, `--detach` and the run directory are in [Plan, run, report](./running.md#run-one-unit).

## On a schedule

```sh
awaywork schedule install      # asks where; this machine is launchd, systemd or cron
```

The job keeps `awaywork watch` running, which starts a run when a window opens and stops it when the window ends (01:00 to 07:00 by default). For GitHub Actions instead, pick it when asked or pass `--with github-actions`: see [Scheduling](./scheduling/index.md).
